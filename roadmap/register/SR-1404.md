A result `from a, b` cannot leave by an early `return` that derives from only one of them: L0316 says "every returning body edge must name the same sources; this edge derives from taken", and does not say how to write a function that answers from either parameter. The same choice written with one way out, a flag and a named result, is accepted. Met writing refine-build's `value_of(how, taken, name)` (friction entry 2).

A list that holds both names borrowed from a parameter and strings made fresh has no spelling: returned with `from how, taken` it is L0316, "this writable from result also carries an independent storage origin", and without a `from` it derives from parameter storage with no `from` clause; pushing a parameter's name into a local list through a helper is L0314 unless the helper's parameter is `escaping`, and then the caller's own parameter is refused as the shorter-lived source. Met writing refine-build (friction entry 21), which copies every name into the step's region before it goes into a list.

Completion: the sources joined over every return edge and compared with the `from` clause, or the refusal's note naming the single-exit form. a spelling for a container whose elements come from a parameter and from an allocator, or the refusal naming the copy as the way, recorded with its reason.

Kept: its activation did not come through R16.25 or R23.20, which touched neither R19.10.

Merged: SR-1419 (register sweep of 2026-11-21).
