The gate's `editor-grammar` job has no Vim, no Emacs, no parser for the Neovim it installs for the server's preference smoke, or `highlight/textmate/node_modules`, so the TextMate tokenizer, the VS Code client test, the VSIX packaging and the Emacs and Neovim parser smokes run only on a developer's host; since R13.79 `./highlight/test.sh` names what did not run. The register sweep after R13.90 met it again: the TextMate tokenizer smoke, the one test of the grammar VS Code loads, runs in no gate job, and whether that job's `npm ci` there should pass `--ignore-scripts`, as the tree-sitter install does, is part of the change. R13.92 met it on a developer's host too: the pinned shell has no Vim, Emacs, Node or Pygments, so `./highlight/test.sh --integration`, which a highlighter change runs before its push, skipped the smokes that change edits, and running them meant taking the editors from the Nix store and `npm ci` by hand, steps no document leads to.

Emacs' `landin-ts-install-grammar` passes a commit ID where Emacs 29 and 30 take a branch or tag for `git clone -b`, so the documented tree-sitter install is believed to fail there. Reported by the review R13.79 answered and not verified: no Emacs was on the fixing host.

Completion: The job installing the editors and setting `LANDIN_HIGHLIGHT_REQUIRE`, so a smoke that cannot run fails; and Emacs' tree-sitter install verified on Emacs 29 and 30, by that job or by hand, and corrected if it fails.
