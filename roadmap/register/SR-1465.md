`scripts/item.py`'s promotion steps say less than they do, as the items running on 2026-11-20 and 21 met them. `promote` pushes main to both remotes in one `git push origin` and reports the promotion failed when the sourcehut mirror refuses, though GitHub's main has moved, so the item has to check GitHub by hand before recording it. `push` fails the same way and then records no gate run, though GitHub took the branch; R16.25 followed its gate with `item.py gate`. `merge-main` on a branch that has already merged main once does not take the promotion token, so main can move under the last gate, which cost R16.23 two gate-and-boards rounds. An agent that is no item can read the token with `item.py queue` but cannot take it. `item.py status` showed finished boards dispatches as queued.

Completion: `push` and `promote` report each remote's outcome apart and go on with what GitHub took; `merge-main` takes the token whenever it merges; a non-item session can take and release the token; `status` shows a dispatch's state as GitHub gives it.
