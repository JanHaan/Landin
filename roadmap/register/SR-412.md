QEMU on an x86-64 host does not keep an arm64 `stlr` before a later `ldar`, which ARMv8 orders (the RCsc rule seq_cst's mapping relies on): QEMU 11.1's TCG ops, from `qemu-aarch64 -one-insn-per-tb -d op`, are `mb rel:all` then `qemu_st_i64` for `stlr x9, [x10]`, and `qemu_ld_i64` then `mb acq:all` for `ldar x9, [x10]`, so nothing lies between the store and the later load, and the x86-64 store buffer lets `runtime/atomic-store-buffering-between-processes` read both old values at `--optimize speed` in every local run, under user emulation and under the FreeBSD arm64 lane's system emulation alike, while the same rounds with a `dmb ish` between pass. Any program built by GCC or LLVM has the same `stlr`/`ldar`. Met in R14.40.

Completion: The fixture targeting FreeBSD arm64 again and its `cross-lanes.json` row removed, with the emulator's ops shown to order the pair.
