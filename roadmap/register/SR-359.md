FreeBSD 14.4's base LLDB, 19.1.7, misreads the stack switch's final `ret` on arm64: in frame 0 it emulates the routine's instructions rather than read its CFI, its emulator loses the stack at `mov sp, x10`, and at the `ret` it reads the return address through x29 and skips a frame. A clang-built switch with clang's CFI fails the same way, every other instruction unwinds right, and the CFI there is the standard epilogue's. So the FreeBSD arm64 switch session records that one stop and does not judge it (`UNRELIABLE_RETURN` in `compiler/tests/debugging/switch_frames.py`). Met in R14.20, gate run 40707225594.

Completion: The exemption removed once that LLDB unwinds the `ret` right, or the reason restated for the version that still does not.
