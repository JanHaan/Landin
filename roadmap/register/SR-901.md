On a native Mac with Xcode's SDK 27.2, the pinned GNAT 16.1.0 compiled the Ada sources but could not link `refine`, so a focused native test run ran no test case. The GNAT bundle's `ld` is a wrapper script that runs `ld-classic` whenever `xcrun --find ld-classic` finds one; it found the Command Line Tools' `ld-classic` 957.1 rather than Xcode's linker 27106.1, and that one ignored the SDK's `libSystem.tbd` as malformed, naming `arm64e.x1-macos` an unknown architecture. `SDKROOT` was set as `compiler/ada/TOOLCHAIN.md` says; the tested pins there are SDK 26.5 and linker 1267, and neither the guide nor the wrapper offers a way to choose the linker. The native Clang adapter checks passed on the same host. Met verifying R13.78's nit fixes on a Mac whose Xcode had moved past the pins.

Completion: The Mac guide, or the build's preflight, naming the linker GNAT will actually run and refusing an SDK it cannot read before the build starts, with the route to a supported SDK or linker.

Kept: No native Mac toolchain setup and no change to the Mac SDK and linker pins has come since R13.78, so the guide still tells nobody which linker GNAT runs.
