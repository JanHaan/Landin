`refine version --json`'s `source_digest` covers the compiler's own sources (D1357), while the library a program compiles against, `core`, `hosted` and `platform`, is named by path alone, and nothing `refine` reports identifies its content or the assembler and linker it runs: two installations that differ only in their library sources report one digest. A build tool keying its cache on what `refine` reports therefore misses a library change; refine-build hashes the three library directories itself on every build and leaves the assembler and linker out of its key. D1387's lockstep compares only the compiler's digest, which is right for a split command built from one tree. Met writing refine-build (friction entry 24).

Completion: `refine version --json` reporting a digest of the library sources it reads and the identity of the assembler and linker it would run, or the reason recorded where a build tool's author reads.
