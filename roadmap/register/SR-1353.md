`scripts/item.py run ITEM NAME -- COMMAND` always runs COMMAND in the item's own worktree, and takes no directory, so a run that builds or tests another checkout, such as a stream's worktree before it is merged, cannot be recorded in the item's state; it has to go through `run_logged.py` by hand, outside what `item.py resume` reports. Met in R18.50 by the roadmap manager.

Completion: `item.py run` takes the directory a command runs in, or says in its help that it runs only in the item's worktree and points at `run_logged.py --detach` for anything else.
