Nothing starts and keeps a FreeBSD VM: the lanes' `--ssh-port` takes "an existing development VM" without saying how to start one, so booting the cached `arm64.raw` behind a qcow2 overlay with the lane's own QEMU arguments, to keep the guest for `image show-unwind` and C comparisons, was read out of `environments/freebsd/vm.py`. Met investigating the FreeBSD arm64 switch session's final `ret` in R14.20. The README gives the shell's build tag and `LANDIN_FREEBSD_EFI`, and since R13.79 the missing-`refine` refusal lists the `refine` executables the build tree holds.

Completion: A `--keep-vm` or boot-only mode that prints the port a later `--ssh-port` run uses.

Kept: The last change to `environments/freebsd/vm.py` closed its console socket and added no boot-only mode, and no planned item names the FreeBSD lanes.
