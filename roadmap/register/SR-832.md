After R13.20's cached STM32H753 RAM run passed on the chip, the cacheless RAM run that followed it by hand was refused before loading with "stm32h753 warm cleanup: could not retire active exception; use the boot check": the cached image's entry returns, and every firmware entry's return ends in the compiler-owned `udf` trap, whose handler loops, so the helper's cleanup, which steps a handler until thread mode, cannot finish. The refusal says what to do but not why the board is in a handler, and the boards guide said the returned board was left as the helper requires. Met recording R13.20's cached profile, whose leg runs the boot check next and so passes.

Completion: The helper recognises the returned trap and retires it, or the returned path ends in a state the warm contract accepts, with a manual RAM run after a cached run as its control.
