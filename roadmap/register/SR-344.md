A fixture can hold only what `refine` prints, never a file an option writes, so an option that writes a report, `--build-report`, `--stage-report` or `--stack-report`, is pinned only by fake-host cases in the test program and never end to end on a real host. Met in R14.20 adding `--stack-report`. R13.20's `c-inputs` key and the recording of a positive, runtime or ABI fixture's ordered `codes` changed what a fixture compares, and neither needed a written file. R13.79 read it and left it as too large for a register sweep: every recorded fixture runs `--dry-run`, so a written-file key needs real emission into a scratch directory, the option's path supplied by the harness, `--record` recording the file, both metadata readers and every Python lane that runs recorded fixtures.

Completion: A fixture key naming a written file and its expected bytes, such as `written: --stack-report=stack.expected.json`, as an item of its own.
