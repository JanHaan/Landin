A view of a local list's block taken through a copy of the list value, `snapshot := numbers` then `xs := vec.used(snapshot)`, is not held against `vec.push(numbers, ...)`, which may move the block `xs` still reads; the same through a caller's `inout` list is L0315, because the parameter's value derives from itself. Met in R13.92 checking SR-1080's loopholes. Since R13.93 a copy of a list the routine has already passed `inout` holds it, since what a call may store in a place is read with the binding; a list made by a call, or copied before any such call, still lends the copy alone.

Completion: The copy deriving from the list it was copied from, so the view holds the original, or the hole stated as a non-guarantee with its reason.
