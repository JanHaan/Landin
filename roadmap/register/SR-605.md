An `rp2350-image-block` image carries one IMAGE_DEF block with no HASH_DEF item, so RP2350's boot ROM boots it without checking a byte of the image: a partly written or corrupted flash image whose first 4 KiB survive is entered as if whole, and a board with secure boot enabled refuses it. pico-sdk's default build does the same, and adds an end block only to close its block loop. Met making the boot kind in R12.30.

Completion: A HASH_DEF item and HASH_VALUE over the image's load map, computed after the link and checked by the descriptions lane, with a board run booting it and refusing a corrupted one.
