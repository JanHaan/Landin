GDB cannot read a `link(thread)` instance in a static Linux program: under `--link=libc` `print counter` gives the selected thread's value, and statically linked it says "Cannot find thread-local storage ... Unable to fetch TLS block address", because GDB resolves `DW_OP_form_tls_address` through the C library's thread descriptors, which a block platform/linux lays has none of (D508). On arm64 ELF the datum has no location at all, since GNU as spells no DTP-relative word. Met checking D508 by hand on x86-64 during R14.40.

Completion: A scripted session printing a thread's instance on every hosted target, the static Linux block carrying what the debugger reads, and arm64 ELF described.
