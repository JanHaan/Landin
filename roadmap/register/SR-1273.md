On NixOS an Xtensa run with `--qemu` alone cannot start the installation's QEMU: the stub loader refuses it, and inside `landin-fhs` it still needs `LD_LIBRARY_PATH` set to the installation's `root/usr/lib/x86_64-linux-gnu` and its `pulseaudio` directory. The README says so and the message names the route, which is still a workaround. Met in the register sweep after R13.90 proving an unlocked run.

Completion: A `--qemu` run routed through `landin-fhs` with its libraries, as `--tools` is.
