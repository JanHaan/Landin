`refine` has no command that runs a module's tests and there is no convention for where they go, so the library's fakes (a memory world, a fake volume, scripted programs) go unused by a program's own tests: each would be a program with its own `main` and reporting. refine-build tested itself through its built executable and a shell script instead, and was written against `blocking.host` rather than the concepts. Met writing refine-build (friction entry 10).

Completion: a test command and a place for a module's tests that run against the library's fakes.

Kept: its activation did not come through R16.25 or R23.20, which touched neither the build tool's design.
