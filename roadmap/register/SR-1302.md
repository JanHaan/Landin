`refine compile --target=xtensa --firmware-entry=start` on the Xtensa reference, the profile a program importing no description gets, links a boot-layout image whose `.rodata` and `.data` are loaded only into DRAM, so nothing at boot holds their contents; with `--build-report` the same request fails with L0501 "cannot measure linked firmware image or map", which names neither the segment nor what to do, and `--firmware-layout=ram` refuses with L0519. Met measuring `cmp-siphash-vectors` in R16.10, which links Xtensa workloads against the chips' own descriptions instead.

Completion: The Xtensa reference's boot layout placing initialized data with a load address in its text region, or refusing it at link time by name, and the measurement failure naming the segment and the rule it breaks.
