A `list` grows by allocate and copy (D356) while the text builder grows by `resize`, so reading 250 MB into a byte list takes 0.40 s against the builder's 0.23 s, and reverse-complement stays on the builder; growing lists through `resize` rewrites the fixtures that pin allocator calls and overflowed a Cortex-M image when tried. R13.79 added `mem.reserve_admit_copy`, which `vec.append_bytes` grows through, and a builder path that keeps the old block while it may still be read (D1122); a list still grows by allocate and copy, and the builder still calls `resize` otherwise.

Completion: Lists grown through `resize` where a provider has it, measured, with the counter fixtures re-decided.
