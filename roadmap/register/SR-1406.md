Refusals met writing refine-build (and one in R16.24's test program) that do not say what to write instead; each is its own code or parser path and closes on its own, and the row closes when the last does:

- L0340 does not say that `utf8` and `[]u8` differ. Passing a `utf8` value where `[]u8` is wanted, `io.write(host, io.out(host), lines.version())`, is "a different reference permission or view from its parameter pattern", without naming `text.bytes(value)`; and a text literal given to a generic parameter, `vec.push(names, memory, "a")` on a `vec.list([]u8)`, makes `item` `utf8` (D138), with no note that the literal is `utf8` and should be bound with its type, as L0304 says for a struct literal. Met writing refine-build (friction entries 4 and 9), which then held no `utf8` at all.
- Inside an `if` or `elsif` arm, `count: usize = text.encode(scalar, room) else begin fail bad_escape end` closes the `if` at that `else`, as [1030] says, but nothing is reported there: the refusal comes later, as L0110 "`elsif` continues no branch that is open here" on the next arm, L0110 "`else` continues no branch", or L0201 on names the arm declared, and none names the `else begin` or says to write `else (problem)`. Met writing refine-build, a 2,000-line Landin program (friction entry 1); found by bisecting with four programs.
- An import path with a hyphen or a dot, `import janhaan/refine-build/lines` or `import github.com/janhaan/refine-build/lines`, is L0110 "this begins no declaration", pointing at the path's rest with [1740]'s note: nothing says that each segment of an import path is an identifier, or which character broke it. A segment beginning with a digit, `import 701_dev/pkg/lines`, is L0011 "this is not an integer any base spells", which says nothing of import paths. Met naming refine-build's package (friction entries 11 and 15), found by trying three spellings.
- A module split over two files needs its imports again in each, as [1450] says, but a use in the second file of a name the first imports is L0201 "`mem` is not declared in any scope this reaches", with [1860]'s note to check its spelling: nothing says that `mem` is imported in a sibling file and that each file has its own imports. refine-build met twenty of them splitting `steps` into `steps.ldn` and `keys.ldn` (friction entry 22).
- `f(lenof "abcde")` and `f(usize(lenof "abcde"))` are refused with L0103, "a call's arguments are never closed", pointing at the string literal, though every parenthesis is closed; `f(lenof s)` of a slice `s` is accepted. Met while writing a test program in R16.24. What is wrong, and what to write instead, the message does not say.

Completion: for each, in its order above: when the two types are `utf8` and `[]u8`, the note naming the conversion, and for a text literal saying it is `utf8` and to bind it first; the refusal pointing at the `else` that closed the `if`, and naming `else (problem)` or parentheses as the way to keep it the call's; each refusal of an import path saying that a segment is an identifier and naming the character that breaks it, a leading digit included; L0201's note, when a sibling file of the module imports the name, saying so and that each file imports for itself; `lenof` of a string literal is accepted in a call's arguments, or refused with a message that names it and says what to write.

Kept: its activation did not come through R16.25 or R23.20, which touched neither L0340's notes and D138.
