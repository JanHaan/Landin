The Cortex-M emitter's local labels, `L3_1` and `Lcm_step_17`, are symbols in the object and the linked image, so `objdump -d` lists a routine as fragments, each label a heading of its own, and a reader looking for `main`'s instructions under `<main>:` finds only its prologue. Met when the corpus's selection check first read every routine as empty past its first label, and took each routine's extent from `nm -S` instead. Merged: SR-874, the same labels making a board record fragile: a record compares the whole linked ELF's hash, local symbols included, and the labels are numbered by the program's item count, so `platform/cortex_m` importing `core/cache` left the RP2040, RP2350 and STM32H753 images' code byte for byte the same and all six of their records mismatched, which `build.py --records=strict` fails the board bundles on and only a physical rerun re-records; R13.20 routed around it with `platform/cortex_m/l1`. The root fix is one: local labels emitted as assembler-local `.L` symbols, outside the ELF symbol table; it changes every board record once and so waits for a physical re-record.

Completion: Labels the listing does not split a routine at, and a record whose identity a library change that leaves the code unchanged does not move, with a control that adds an unused import; or the lane guide saying where a routine's instructions are found and the record comparison saying what it is sensitive to.
