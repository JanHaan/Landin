# Q-122 — Does the fold also lift the scalar element of an inferred module array?

Asked by R19.20 on 2026-11-21.

D1664 lifts two scalar-element lags: a counted repetition and `lenof` of a
literal take any element shape, as a literal does. R19.20's reading found a
third that D1664 does not name. At module scope an inferred array, a
literal (D26) or a counted repetition (D35), still takes only a scalar
element. `points := [first, second]`, with `first` and `second` module
structs, is L0304, "an inferred module array takes a scalar element; write
the array type for any other", pinned by
`negative/r720-inferred-module-array-scalar-element`. The same literal with
its type written, `points: [2]point = [first, second]`, is accepted, and
it forms the same static image. So the boundary only decides whether the
element type is written, not whether the image can be formed. Lifting it
widens the language and is not a removal, which is why it is yours, and
D1664's words reach only as far as "as a literal does", which a module
literal does not.

**Options:**

1. Lift it with the other two in R19.90. At module scope as at local
   scope, the first element, or the repeated value, gives the element type
   whatever its shape. [1940]'s known-value rule still decides which
   elements can form an image. D26 and D35 are then marked superseded, and
   the fixture becomes a positive one.
2. Keep it. D26's and D35's scalar sentences stay as recorded boundaries,
   D241 says so, and the fixture stays negative.

**Recommendation:** option 1. The typed form already forms the image, so
the boundary is a remaining case of one shape being inferred at one scope
and not at the other. That is the kind of special case SC-24 removes, and
R19.90 changes the same inference routine, `Infer_Literal_Shape`, for the
local repetition anyway.

**Default until answered:** the module boundary is kept. R19.90 lifts only
the counted repetition and `lenof`, as D1664 says, and leaves D26's and
D35's scalar element as recorded boundaries.

**What waits on the answer:** R19.90's scope by one case, a few lines in
`Infer_Literal_Shape` with one fixture turned positive. Nothing before
R19.90 waits.
