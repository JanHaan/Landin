# Q-11 — How does `refine` find external commands, and how do help and completion list them?

Asked by R18.10 on 2026-11-18.

The command inventory's second and seventh questions. Once the bare-source
form `refine FILE` is retired (R18.40), an unknown `refine NAME` can name a
command, and something must say where `refine-NAME` is looked for and how
`refine help` and shell completion show it. These are the rules a user and
a tool author meet, and so yours.

Precedents: `refine` finds its library beside its executable through
`Landin.Platform` (D275), and D275 refuses environment variables and
configuration files as a second place to be wrong. The flake already
installs helpers in `$out/libexec/landin`. The assembler and the linker
driver are found on PATH. Help, completion and `refine explain` each list a
fixed set of commands today.

**Options:**

1. Built in first; then `libexec/landin/refine-NAME` beside the
   executable, found through `Landin.Platform` as the library is; then
   `refine-NAME` on PATH. `refine help` lists external commands under a
   heading of their own from a scan of both places at run time, and
   completion delegates to `refine-NAME --complete`, as git does.
2. The same order without PATH: only shipped split commands are found,
   and a contributed tool is run by its own name.
3. PATH alone, the shipped split commands installed beside `refine` in
   `bin/`.

**Recommendation:** option 1. It fits D275 and the flake's layout, needs no
variable or file, and costs only the order rule; a built-in can never be
shadowed.

**Default until answered:** a built-in command wins, then
`libexec/landin/refine-NAME` beside the executable, then `refine-NAME` on
PATH; help lists the external ones under their own heading from a run-time
scan, and completion asks `refine-NAME --complete`.

**What waits on the answer:** R18.10's close, and R18.50, written to this
default.

**Answer (2026-11-18, the maintainer):** option 1, with a requirement of
the maintainer's own: `refine` must decline to run a `refine-NAME` that is
not compatible with it. Recorded as D1384, a shipped name being looked for
beside `refine` alone, and D1387, which says what compatible is and how it
is checked: a description each command prints, its source digest equal to
`refine`'s for a shipped command, and a refusal that says what to do. Both
are R18.50's to implement. Closed.
