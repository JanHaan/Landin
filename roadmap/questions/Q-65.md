# Q-65 — Does a release also move a `latest` tag on the container images?

Asked by R23.10 on 2026-11-20, when the item was planned.

The maintainer decided on 2026-11-19 that the user and contributor images
under `ghcr.io/701-dev` are published only at a release, each tagged with
its version. A `latest` tag that every release moves is what `docker run`
takes when no tag is named, so it is the shortest command the
documentation could print; it also hands a user the next release's
changes, the breaking windows of R19 and R20 among them, without their
asking. A tag published under the organisation's name is outward-facing
and cannot be withdrawn from those who already pulled it, so the choice is
the maintainer's.

**Options:**

1. Version tags only; the documentation names the version.
2. Each release also moves `latest` on both images.
3. `latest` on the user image only; the contributor image, which must
   match a checkout's pins, keeps version tags only.

**Recommendation:** option 1 while the language still breaks between
releases; option 3 once it does not. A `latest` added later costs nothing,
and one withdrawn breaks whoever relied on it.

**Default until answered:** the images carry version tags only and no
`latest`, and the documentation names the version.

**What waits on the answer:** nothing in R23.10's work; only the tags its
release workflow step moves and the command the documentation prints.
