# Q-82 — Does a type application's fixed actual fold as an array length does (SR-1237)?

Asked by R19.10 on 2026-11-20.

Q-5 sent SR-1237 to R19.10. Today an array length folds D136's closed
forms, an integer compiler fact (D1321) and `sizeof` or `alignof` of a
scalar (D1321, D1340), but a fixed actual of a type application is only
an integer literal or a forwarded fixed formal (D135). So
`[compiler.word_size]u8` is a type and `buf(compiler.word_size)` is
refused, and a program sized by the target writes the number or routes it
through a module value. Two rules for one kind of value is what R19 sets
out to remove, and the answer is a language rule, so it is yours.

**Options:**

1. One rule: a fixed actual is any expression an array length folds, with
   the same refusals and the same target-dependent identity (D139). D135
   and D1321 are amended; it lands with the group that takes the
   declaration spellings, or as its own small item in R19's window.
2. D135 stands: a fixed actual stays a literal or a forwarded formal, and
   SR-1237 is retired with that decision recorded.

**Recommendation:** option 1. It is additive, removes a difference a
reader has to learn, and the fold it reuses already exists.

**Default until answered:** D135 stands as it is and SR-1237 stays
scheduled on R19.10.

**What waits on the answer:** R19.10's close; nothing else.
